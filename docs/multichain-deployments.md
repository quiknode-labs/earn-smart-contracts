## Quick verification

Re-query the live state at any time:

```bash
# Check proxy presence + owner + vault count on all 7 chains
./node_modules/.bin/tsx scripts/estimate-deploy-gas.ts

# Per-chain DB ↔ on-chain delta check (dry-run)
./node_modules/.bin/tsx scripts/seed-vaults-on-chain.ts <chainId>

# Reconcile DB to match on-chain truth
./node_modules/.bin/tsx scripts/reconcile-approved-vaults-db.ts
```

## Deployment artifacts

Forge broadcast files are gitignored but persist locally at:

```
smart-contract/broadcast/Deploy.s.sol/<chainId>/runWithVaults-latest.json
```

These contain the full transaction details including gas used, tx hashes, and the deployed implementation address.

## Adding more vaults later

The DB-driven flow is:

1. Insert into `approved_vaults` (Supabase) for the chain — see `scripts/seed-approved-vaults.ts`
2. Run `./node_modules/.bin/tsx scripts/seed-vaults-on-chain.ts <chainId> --execute` — calls `batchAddVaults()` on the proxy with the delta

## DO NOT

- ❌ Change the salt version in `smart-contract/script/Deploy.s.sol` (would generate a new proxy address on subsequent chains, breaking determinism)
- ❌ Use a different deployer key (would also break determinism)
- ❌ Hand-edit the proxy address in any config file
- ❌ Add vaults via `addVault` from a wallet other than the owner
